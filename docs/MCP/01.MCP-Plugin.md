# Composable Analytics MCP Plugin

The Composable Analytics plugin lets you work with your Composable server by asking Claude in plain language. Claude can build, run and debug DataFlows, write and preview QueryViews, build DataPortals and WebApps, and explore DataRepositories. It works through a local connector (an MCP server) signed in as you, so it can see and change only what your own account can. This page is a short reference.

## Requirements

- A Windows PC with an x64 (Intel or AMD) processor. The connector runs on your computer.
- A Composable server you can sign in to, and an API token for your account.
- Claude Code.

## Install

1. Add the marketplace and install the plugin in Claude Code:

    ```
    /plugin marketplace add ComposableAnalytics/public-marketplace
    /plugin install composable-analytics@composable-analytics-marketplace
    ```

2. Ask Claude to "set up Composable Analytics". Claude installs the connector and gives you a setup command.
3. Run that setup command in your own terminal. It asks for your server's address and your API token; typing the token is hidden, and the token is saved in a protected file in your Windows profile.
4. Reconnect the connector, or restart Claude, and ask "Am I connected to Composable Analytics?"

!!! note
    Never paste a token into a chat with Claude.

!!! note
    Windows may show "Unknown publisher" or "Windows protected your PC"; for a program you got from this plugin, choose **More info**, then **Run anyway**. Smart App Control, where it is on, blocks these programs outright.

The connector updates itself the next time it starts after a new plugin version. To remove it, ask Claude to "uninstall Composable Analytics".

## Profiles and Tokens

A profile is a named server address plus its token. Create or update one with:

```
ca-mcp setup --profile <name> --base-url <url>
```

Add `--default` to set it as the default profile. The first profile you create becomes the default automatically. Settings are stored under `%LOCALAPPDATA%\Composable Analytics\MCP`; tokens are never written to the config file.

- **Launching against a profile:** start the connector with `--profile <name>` to pin it to that server. The target stays fixed until you reconnect.
- **`default_profile`:** the profile used when nothing else names one. Change it with `ca-mcp profile set-default <name>`.
- **`.yeti` project file:** a small, credential-free file committed to a project that names the server everyone on the team should use (by `base_url`). It never holds a token and cannot change safety tiers. Ask Claude to set one up.

## What You Can Ask For

Claude picks the right workflow from what you ask; you don't need to name it.

| Workflow | What it does |
|---|---|
| Set Up Composable Analytics | Install, configure, repair, or remove the connector. |
| Create DataFlow | Build and validate a new DataFlow. |
| Edit DataFlow | Safely modify an existing DataFlow. |
| Run DataFlow | Run a DataFlow and inspect its results. |
| Debug DataFlow Run | Diagnose failed or empty DataFlow runs. |
| Run TestSuites | Create, run and read TestSuites of DataFlow tests. |
| Transfer DataFlow | Move a DataFlow safely between servers. |
| Web-Activated DataFlows | Build HTTP-activated DataFlow endpoints. |
| Build QueryView | Build, preview, run, and debug a QueryView. |
| Build DataPortal | Build, change, style, and inspect a DataPortal. |
| Build WebApp | Create, edit, build, and copy a WebApp. |
| Manage Resources | Share, clean up, and manage alerts on resources. |
| Explore DataRepositories | Read collections, relationships, and DeepQueries. |

## Safety Tiers

Every tool belongs to one tier: **read**, **write**, **execute** or **dangerous** (deletes and other destructive operations). The `allowed_tiers` setting on a profile controls which tiers are available; the default is `read,write,execute`, so dangerous operations are off until you opt in:

```
ca-mcp profile config <name> allowed_tiers=read,write,execute,dangerous
```

Then reconnect. Tools in a tier that is not allowed are not registered at all.

Write, execute and dangerous calls also require an explicit confirmation flag (`confirm_write`, `confirm_execute` or `confirm_dangerous`), so you can let Claude read freely and still approve every change. When a call is refused, the connector replies with `blocked: true` and a reason:

- reason names a missing `confirm_<tier>` flag: the call needs confirmation;
- reply includes `use_tool`: the request went to the wrong tool, and `use_tool` names the right one;
- reason names no flag: the call was refused outright, for example because its tier is not allowed.

A profile can also list read-only **peers** (other profiles) so Claude can read from a second server, for example to compare environments. Peers are always limited to the read tier, whatever their own `allowed_tiers` say.
